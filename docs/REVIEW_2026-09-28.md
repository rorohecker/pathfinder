# Folder-sync and audit-correction review — 2026-09-28

Scope: the current working tree, including the one-way folder-sync feature and the changes tracked in [IMPLEMENTATION_STATUS_2026-09-28.md](IMPLEMENTATION_STATUS_2026-09-28.md). This is a code and automated-test review. It does not claim that all possible bugs have been found or that the desktop UI has been exercised on every Windows configuration. The original 44 findings, their evidence, and their proposed fixes are in [AUDIT_2026-09-28.md](AUDIT_2026-09-28.md).

## Outcome and coverage

The new sync flow retains the existing folder-compare dialog structure, adds an explicit source-to-destination direction, defaults destination-only deletion to **off**, requires a fresh preview after option changes, keeps previous versions, and exposes conflicts and run results. The main file-list and navigation layouts were not redesigned. The search reference replaces the redundant operator/filter chips with clickable examples. This is a reasoned static UX assessment; a visual, keyboard, screen-reader, high-contrast, theme, localization, and DPI pass still needs a running packaged app.

I traced the sync planner, executor, cache, recovery journal, cancellation, dual-pane refresh, search/filter interaction, duplicate scan, AI catalog/locking, operation terminal state, and the Slint flows affected by those changes. The review also rechecked the 44-item audit status table. It remains **11 addressed, 17 partial, and 16 open** in the limited sense defined by that table; this review does not silently promote a partial fix to complete.

## Bugs and UX regressions corrected during this review

| Area | Problem found | Correction |
| --- | --- | --- |
| Sync preview | Conflict rows only said “skipped,” so users could not tell whether the cause was a newer destination, a link, a type mismatch, a case-only name, or a blocked parent. | The planner stores a reason per conflict. Preview and saved report display it; blocked children have an explicit reason. |
| Sync results | Every completed result row inherited the error color because status matching only covered preview labels. | Result rows carry a separate state; done, skipped, cancelled, and failed now have distinct status colors. The second line displays errors and conflict reasons. |
| Sync cancellation | Runs with many kept extras or conflicts could keep processing journal rows after Stop because cancellation was checked only before writes. | The executor checks cancellation before every item. A test stops during skipped entries and confirms later entries are untouched. |
| Sync preview scale | Toggling “Hide same” cloned the entire plan, potentially including 200,000 paths, fingerprints, and hashes, on the UI thread. | The existing plan is borrowed for a redraw. The control no longer duplicates the scan result. |
| Sync row affordance | Rows in sync mode showed a pointer/hover state but clicking them did nothing. | Sync rows now use a neutral cursor and no hover/click affordance; ordinary compare rows retain navigation. |
| Sync report triage | The first 500 rows could be filled with unchanged or successful items, hiding conflicts and failures. | Preview lists conflicts and proposed changes first. Reports list failures, cancellations, and skips first. The summary discloses the 500-row display cap. |
| Sync controls/recovery | Changing exclusions while applying, or clicking the overlay backdrop, could mislead users about whether a run was still using the reviewed options. A failed apply did not expose its history directory. | Exclusions and option toggles are disabled during work; outside clicks do not close an active run; the close label says “Stop & close”; failures expose the history folder when present. |
| Compare/sync overlap | Starting ordinary folder compare while a sync worker was still running could replace the compare dialog with a late sync result. | The compare prompt now waits for the active sync task to finish. |
| Dual pane | A sync refresh could refresh the right pane twice when it was active and leave the left pane stale. | Refresh addresses primary and secondary panes explicitly. Primary search results are recomputed when needed. |
| Path search | A path match was put directly into visible rows, then a filter rebuilt rows from another source and erased the match. | Path matches populate the search result source before filtering; immediate search reports misses. |
| Async result polling | A rare UI borrow failure after taking a sync or duplicate result could discard it and leave the overlay running indefinitely. A second producer could also publish between taking a result and clearing the ready flag. | The controller borrow is acquired before consuming the pending result; the ready flag is cleared while the result-slot lock is held. |
| Operation queue | A native-delete failure after queue start lacked a terminal queue outcome. | The failure path now finishes the queue item as failed. |
| Duplicate scope | Similar-image discovery used the primary directory even when the secondary pane was active. | It uses the active directory. |
| Search input | Extremely large `modified:` numbers could overflow while multiplying time units; non-finite or out-of-range `size:` values could be accepted incorrectly. | Numeric parsing uses checked bounds; new regression tests cover malformed extremes. |
| AI update | Failure while writing the updater lock owner's PID could leave an empty lock file. A malformed catalog could request extreme or zero-sized classifier input. | Lock-write errors clean up the file; catalog shape bounds are checked, with a regression test. |
| Search help | The new reference read like static documentation and did not let users try its examples. | Examples now fill and run a search with one click. |

The sync regression tests also cover read-only preview, deletion opt-in, version preservation, destination/source changes after preview, nested deletion, overlapping roots, exclusions, newer-destination conflicts, blocked child conflicts, Windows case-only names, and stop-after-first-copy. ## Material remaining issues and the fix to pursue

### Priority 1: sync correctness and recovery

1. **Metadata-based fingerprint cache can miss a same-size edit with preserved timestamps.** The planner accepts a cache row when file kind, length, created time, and modified time match; it then skips hashing. A tool that edits bytes while preserving metadata can make the next preview say “same.” Offer a “Verify contents” mode that hashes all common files, or use a trustworthy change journal and invalidate on every relevant write. Until then, cached equality is an optimization, not proof of byte identity. See `folder_sync.rs` `plan`/`CacheRow`.
2. **Crash recovery is inspectable but not automatic.** A crash after moving a destination file into `versions/` and before installing its replacement can leave the destination path missing. `report.json` starts before writes and `events.jsonl` records progress, but events are synced in groups of 16 and there is no restart reconciler. Introduce a durable per-item prepare/commit journal, fault-inject every rename/write point, and offer a recovery UI that verifies current files before restoring. Preserve the existing history until a user resolves it.
3. **External writers still race item preconditions.** Source/destination fingerprints are rechecked before an item, but checking and renaming are not one atomic operation. Test and harden Windows reparse/junction cases with disposable roots and identity handles, especially for destination ancestors, and reject a changed ancestor before committing. This also applies to the earlier archive/operation findings.
4. **Full pre-apply review is capped at 500 rows.** High-risk rows are prioritized, but a large job can have more than 500 changes/conflicts and no full export before Apply. Provide a paged/virtualized preview or exportable complete plan with counts per action and a confirmation for hidden changes. The saved full report is only available after execution.
5. **Windows metadata fidelity is limited.** Staged copies preserve the default file stream and modification time, and set basic permissions, but do not explicitly preserve alternate data streams, ACLs, creation time, hard-link identity, or every attribute. Links and reparse points are skipped as conflicts. State this contract in the UI, and either implement verified metadata-preserving copies or keep the feature scoped to ordinary content mirroring rather than full backup fidelity.

### Priority 2: responsiveness and clarity

6. **Preview has no scan progress beyond a status sentence.** The first run hashes common files and can traverse up to 200,000 entries per tree. Slow drives or cloud paths may look stalled. Emit scanned-entry and hashed-byte progress, provide a bounded worker budget, and show a clear cancellation acknowledgement.
7. **History retention has no space policy.** Every replaced/deleted version stays until manual cleanup. Show predicted destination and history space, permit configured retention with a safe prune preview, and never remove a version needed by an incomplete run.
8. **Exclusions are a small custom glob dialect without validation.** An overly broad pattern can hide files from the preview and deletion plan without a diagnostic. The current “excluded” count measures pruned roots, not every descendant, and the matcher normalizes and splits patterns for each visited path. Compile patterns once, label subtree counts precisely, show matches per pattern, reject unsupported syntax, and provide a sample-path tester. Keep excluded trees out of both source and destination operations.
9. **Display text can be truncated.** The sync dialog fits the declared minimum 900×550 window and its list scrolls, but long paths, conflict reasons, translations, and scaling can elide. A selected-row details view or accessible tooltip should expose the complete path and reason. The delete toggle and example rows are custom pointer controls without proven keyboard/screen-reader semantics.
10. **Indexed path search can show deleted paths.** The broad indexer does not prune old paths after an incomplete batch, and the synchronous path-search fallback returns index rows without rechecking them. Filtering up to 1,200 paths against the filesystem on the UI thread would create a worse stall on slow drives. Move path search and its liveness checks to a cancellable worker, page until enough live matches are found or a defined work budget is reached, and reconcile stale rows in the background.

The **open** findings remain in the backlog, not fixed by this review: registry ownership (10); scoped composable tags (15); incremental AI indexing and query planning (20–22); thumbnail/cache and UI-model efficiency (23–25); bounded text diff (29); truthful accelerator detection, atomic model updates, and runtime verification (32–34); shortcut collision handling and accessibility (39–40); shell context-menu identity and trusted updater outcome (42–43). These are the major remaining bugs, UX gaps, and performance opportunities from the original document. Prioritize data safety and result correctness before optimizing throughput.

## Validation matrix and release gate

It does **not** validate visual alignment or interaction on a live desktop.

Before describing the whole feature as fully validated, run a packaged Windows build on disposable folders and check: source direction with each pane active; no-op second run; update/delete with recovery from `versions/`; changed source and destination after preview; stop during hashing and transfer; unreadable/locked files; low disk space; forced crash at each staging/rename/journal point; overlapping/UNC/reparse roots; more than 500 conflicts; background/minimize/resume; mouse, keyboard, Narrator, high contrast, light/dark themes, 100–200% scaling, and long translated labels. Measure preview latency, UI-thread stalls, peak memory, and disk I/O on a large local tree and a slow/network tree. Keep such tests isolated from user data.
