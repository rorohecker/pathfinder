# Security review — 2026-09-29

Pathfinder is a local file manager, not a vault. It should use the current Windows user's file permissions and support Windows volume/file encryption. It should not silently encrypt a user's ordinary files or introduce an application password: doing so would break interoperability with Explorer and other applications and create key-recovery risks. BitLocker or Windows device encryption protects data at rest when a device is lost; EFS can protect selected NTFS files where available. Those Windows facilities require separate user or administrator setup.

The new content index is opt-in per folder. Extracted document text and optional local OCR output are stored in a separate SQLite database under the user's local app-data profile, in plaintext unless the volume is encrypted. Disabling OCR removes indexed image and PDF text, including normally extractable PDFs, which can be reindexed without OCR on refresh. Removing a root deletes its documents and FTS entries, vacuums the database, and truncates the WAL. Backups, system snapshots, filesystem slack, and other copies are outside the app's control. The privacy UI now states that GitHub update checks happen automatically and that installer downloads require a click.

Update assets are restricted to the official GitHub Pathfinder release path, the expected version and x64 installer names, an uploaded asset of plausible size, and a GitHub-provided SHA-256 digest. Downloaded bytes must match both advertised size and digest before execution. Staging moved from a shared temp folder to the user's local app-data area; the Windows helper rejects batch expansion characters in embedded paths and is created without overwriting an existing helper. The release workflow now generates GitHub build-provenance attestations for both installers. These checks do not replace publisher Authenticode signing or an independent trust root; installers are not yet code signed.

Per-user shell registration now backs up values before changing them and restores only values still owned by Pathfinder. It avoids removing whole keys that may have been taken over by another app. Normal file copies are staged beside the destination and published only after the source fingerprint is rechecked. Transfer plans persist checkpoints; concurrent retries of the same job are blocked. Cross-volume file moves copy first, verify, and only then delete the source; interrupted moves with both copies remain visible for recovery.

Remaining limits: folder copies and cross-volume folder moves still use the older recursive path and are not fully transactional. Replacement backups and sync history require manual recovery after some crash points. A size-and-mtime fingerprint can miss a same-size edit with a restored timestamp. Existing live PDF search still uses a less bounded extraction path than the new persistent index. OCR language availability and installer helper execution need runtime tests on supported Windows configurations. Code signing, a durable installer outcome receipt, and broader fault-injection coverage remain release-hardening work. Do not describe the app as end-to-end encrypted or crash-proof.
